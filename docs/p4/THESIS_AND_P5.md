# 毕业设计素材与P5独立认证计划

## 可复用的系统说明

本系统将客诉邮件作为版本化输入，由LangChain封装模型请求和执行边界，使用严格结构校验及原文Evidence将结构化结果绑定到输入。多Issue保留各自原因、情绪、紧急度、风险、客户重要性、业务顺序和不确定归属。SQLite将预测、草稿版本与审核操作分开保存；人工审核后只能形成模拟发送回执。模型负责语言理解与回复建议，程序负责契约、已知矛盾、防止无权限动作及可追溯持久化；两者不能互相替代。

论文系统设计可直接使用 `ARCHITECTURE.md` 的架构图、`DATA_AND_WORKFLOW.md` 的表设计与状态图，以及实际截图和 `DEMO.md` 的操作流程。测试章节分别描述单元/SQLite集成、Streamlit AppTest、实际浏览器、历史raw只读诊断；不能将AppTest改称浏览器E2E或把fixture正确率当模型准确率。

## 数据来源说明

历史400封邮件由确定性模板程序生成；应表述为“程序模板生成的合成邮件”。既不是消费者真实邮件，也不能改称LLM生成。研究者批准参考、助手开发参考、独立人工标注和真实消费者数据必须分开。新40为开发代理编写的探索性文本；其生成身份也不能追溯改写历史400来源。

若导师要求LLM生成数据，后续可建立 `llm_synthetic_v1` 新数据集，保留provider/model/Prompt参数、每次request/run/input/raw hash、生成时间、usage、失败、抽样随机种子、改写/翻译父族关系以及人工筛选记录。不能在旧400行上换来源标签。真实生成需要单独授权模型、最大调用次数/费用和可发送数据范围，本轮未执行。

## P5：尚未授权执行的研究计划

1. 在冻结本候选后，由未参与开发的人工作者准备新场景，按商品/服务/配送/多Issue/风险/不确定信息分层；模板、近重复、同源翻译按族隔离。曾暴露的24、32、新40及N03变体都只作开发回归，不改名holdout。
2. 两位独立标注者在看不到模型输出的情况下标注Issue数/粒度、投诉状态、原因、来源证据、情绪、风险、紧急度、客户主次与请求；回复另用18维rubric。分歧由第三方仲裁。登记标注人、时间、版本、理由和hash；未标注不填0。
3. 预注册冻结候选、Champion、完整接受profile、Prompt/Schema和代码hash、分母、paired指标、严重漏报定义、停止规则及模型/时间混杂控制。A/B同输入、交错调用，同样纠错机会，分别报告首轮和工作流。
4. 在单独真实预算授权后执行。所有失败、重试或纠错都计额度；未知发送/用量/身份/持久化异常停止。不能用旧P3.9剩余1次或已耗尽P3.10封套。预算只是未来提案，不是本轮批准。
5. 报告契约接受、独立字段/整封/Issue指标、严重风险漏报与误报、回复内容质量、人工修改率、阻断率、调用数、tokens、成本、延迟与不确定区间。统计代码做确定性计算，模型自评不替代Gold。
6. 若关键安全漏报未达预注册门槛，继续保持人工审核和模拟发送，发布负结果并停止晋升。真实SMTP/CRM须另行产品授权、角色/渠道验证和安全评审，P4候选没有该能力。

当前可交付的是可运行、可追溯、有人审门禁的单机毕业设计候选版。独立模型质量认证、完整人类回复评测和生产外发仍未完成。

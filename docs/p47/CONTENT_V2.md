# P4.7 V2 演示售后申请与安全情绪变体

2026-10-28，Asia/Shanghai。本增量采用新模块 `service_scenarios_v2.py`，保留 P4.7 v1 的原文、回复、策略、输入/输出hash和历史工作库。没有修改 N04、真实 raw、Gold 或历史研究结论。

## 依据与最小范围

V1 已能区分客户待补资料和商家核实责任，但只说明“由人工评估适用选项”，在演示中缺少可看见的申请步骤。V1 安全案例还用“幸好没摔倒”强调了测试条件。本增量把两个最早失效环节分别交给策略及场景模块：新增明确的演示申请规则，并提供担忧、平静、生气三种自然表达。没有让审核层代替内容策略，也没有降低安全门禁。

新增4个来源身份，与旧场景名称不重名：

| 场景 | 客户表达与事实 | 处理方式 |
| --- | --- | --- |
| 骑行安全风险 · 担忧（v2） | “现在想到那一下还是很后怕。我不敢再骑了……” | 先理解担忧；severe/high、必须人工；停止使用，给申请路径 |
| 骑行安全风险 · 平静（v2） | “目前没有再使用。请说明……怎样申请检查……” | 认可已停用并说明流程，不编造害怕或愤怒；仍为severe/high |
| 骑行安全风险 · 生气（v2） | “才骑两次就出这种问题，真的太让人生气了……” | 承认安全质疑和处理负担；情绪不替代故障事实，也不影响severe/high |
| 配送包装受损 · 售后申请（v2） | 保留已知 DEMO-24031、外包装照片及本体状态未知 | 不重复索要编号、不要求重新拍照；可提出申请，人工核本体状态与订单 |

三安全变体共享同一明确的客户陈述：“昨天下班骑折叠车时，车架锁扣突然自行打开，车身明显晃了一下。”三个输入均不以“无人受伤/幸好没摔倒”作为测试提示，也不虚构已经受伤。风险依据是骑行中承重连接失效，不是客户情绪。三份输入独立hash，风险Evidence指向相同事实文字。

## 明确但有限的演示规则

`DEMO_AFTERSALES_POLICY` 的标题为“演示售后申请规则 v1”，版本 `p47-demo-aftersales-application-v1`，注明它是项目编写的本地演示规则，并未接入实际商家条款。

- 可提出维修、更换或退货申请，并说明偏好；提出申请不等于符合条件或已批准。
- 只补充当前未知的订单、型号和商品状态；保留已有照片，不冒险取证。
- 由人工核订单记录、商品情况和必要检查结果后确认适用方案。
- 未确认前不自行寄回或拆修，寄回方式也需人工确认。

没有设定实际商家期限、运费承担、处理时限或补偿标准；这些列为 `unknown_terms`。没有优惠券或退款承诺。本系统未真实提交申请、预约检查、转接坐席或执行退换。

回复更具体地告诉客户怎样申请，例如安全场景：

> 您可以提出维修、更换或退货申请，并说明更倾向哪种处理方式。请提供订单编号和车型，人工售后需要结合订单与安全检查结果确认适用方案。在人工确认处理方式前，请先不要自行寄回或拆修，寄回方式等具体步骤也需一并确认。

配送场景保留“商品本体是否受潮/破损”的不确定性，并说明“提出申请不代表已经获批”。演示政策在Copilot来源区展示，客户回复不插入hash或内部版本术语。

## 身份、兼容与验证

新增场景版本为 `p47-authored-aftersales-scenarios-v2`，回复策略版本 `p47-service-reply-policy-v2`。配置绑定 `service_policy_version/hash`、`demo_aftersales_policy_version/hash`、`scenario_version/hash`、`fixture_hash`；scenario hash还包含完整策略对象。`strategy(case)` 校验来源原文、接受状态、输出及各身份，不能把v2规则静默嫁接到v1或伪造输入。

接口保持 `SCENARIOS / example / ServiceCopilotFake / strategy`。UI按名称分派版本，路由按确切策略版本取建议；v1旧库继续用v1策略。三安全变体必须人工，配送需要人工确认；接管并不批准方案，也不能解除错误分析阻断。LangChain仍只是 `RunnableLambda` 固定输出编排，没有新增模型推理。

新增离线专项 `test_p47_content_v2.py` 验证三种情绪下相同风险、完整正式服务/SQLite重读、演示政策来源/hash、已知资料不重复索要、篡改被拒及v1身份保留。它验证工程和显式内容约束，不提供未经真人复核的准确率。研究者仍需检查语气自然性、申请步骤是否易懂，以及明确的演示政策是否被误解为实际商家承诺。

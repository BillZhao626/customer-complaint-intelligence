## 本轮产品行为

- 左侧支持搜索、状态筛选、会话摘要和当前选择，历史工程坏例收在次级入口。中间区只显示客户消息、已保存模拟回复和当前草稿；右侧是诉求、处理建议及折叠依据，不重复铺满整份草稿。
- 普通咨询预填有来源的回复建议；操作者明确核对后可轻确认并模拟发送，无默认重审核弹窗。修改正文需保存新版本；被退回/拒绝后须实际编辑才可重新确认。
- 信息不足、多诉求、售后条件等给人工确认；安全、权限、强烈不满、无法识别或明确人工请求进入接管路径。主动转人工与客户请求都有独立不可变事件，接管和批准分别记录。
- 担忧、平静、生气三种骑行结构失效案例均 severe/high。原故意低估分析继续保留并阻断，修改回复、接管或勾选不能解除分析错误。
- 演示售后申请规则说明可以提出维修、更换或退货申请、应补哪些资料、由人工核哪些记录；它不是实际商家政策，不能据此确认资格、期限、运费或批准。
- 新版证据问答按当前预填草稿/接管/审批状态说明下一步，分开客户资料与内部核实并引用绑定策略；旧问答身份与历史记录不改。

## 建议人工体验顺序

1. 普通咨询：读客户问题与来源标记 → 编辑或核对草稿 → 明确确认 → 本地模拟回执。
2. 配送受损：核对已送达、已有订单和照片 → 补商品本体状态与申请偏好 → 查看演示规则 → 人工确认回复。
3. 普通主动转人工：转人工 → 等待人工 → 接管 → 编辑/保存 → 确认及模拟；检查手稿没有丢失。
4. 客户要求人工：打开对应会话，确认已记录等待人工及原因 → 接管；不把它误认为真实坐席已连通。
5. 安全案例：对比三种情绪 → 接管 → 核事实与安全提示 → 审核 → 模拟；再打开旧低估坏例，确认不能放行。

以上操作仍需研究者自行最终验收。完整步骤的自动化与真实浏览器证据范围见 [验证报告](VERIFICATION.md)，不要用 AppTest 结果替代尚缺的 V2 浏览器复验。

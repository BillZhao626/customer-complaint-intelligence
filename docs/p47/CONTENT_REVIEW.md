## 新旧版本边界

旧 `product_demo.py`、`copilot_demo.py`、P4/P4.5 场景、原实验输入/输出和故意错误分析均保留。新目录为 `src/application/service_scenarios.py`：

- 场景版本：`p47-authored-service-scenarios-v1`。
- 沟通策略版本：`p47-service-reply-policy-v1`，`POLICY_HASH = digest(POLICY)`。
- 每条输入有独立 `email_id` 和 `input_hash`；`fixture_hash` 绑定输入与完整预写输出；`scenario_hash` 绑定版本、输入、预写分析和分流/回复策略。
- `ServiceCopilotFake` 通过 LangChain `RunnableLambda` 复用正式 AnalysisService 的解析、原 v3.1 契约和持久化。输出是开发者预写合成内容，不是此次模型推理。主产品来源仍明确标为离线预写。
- `strategy(case)` 仅对版本/hash/原文/输出均匹配的新来源返回建议。建议不批准分析或草稿，也不解除质量阻断。旧案例不会隐式套用新策略。
- `scripts/p47_demo.py` 默认建立9个新案例，全部未审；自定义模式不加入默认种子。`--include-engineering` 可另加原失败/故意低估样例。目录必须新建，仓库内仅允许 `.local/p4/`。

所有新场景均为开发暴露的合成案例，不继承旧参考标签，也不是独立 holdout。没有改写历史研究结论或把合成数据称为真实消费者邮件。

## 九类场景审阅

| 场景 | 已知事实与不确定性 | 回复路径及开发审阅结论 |
| --- | --- | --- |
| 产品功能咨询 | 型号 DemoCam C200 已知；官方连接规格、电脑环境未知 | 直接复述功能诉求，不反复问型号；补接口/系统信息，提醒先别急着买转接头；AI建议层，仅拟补资料回复 |
| 配送包装受损 | 已送达、包装湿破、照片已拍、订单已知；商品本体未检查 | 共情后保留包装与已有照片；问本体状态；受潮电器不通电；人工确认适用选项，不编造延误或制造原因 |
| 商品售后故障 | 台灯不亮、未拆机、影响工作；型号/订单及原因未知 | 道歉并承认影响；暂停使用、不拆机或反复通电；收集必要信息，由人工确认维修或换货 |
| 多问题协同 | 抽屉磕碰、取件爽约、发票漏项三个独立证据跨度 | 先避免再次磕碰，再分别回应取件和账单；保留三个路由，未把取件或发票调整说成已执行 |
| 骑行安全风险 | 车架锁扣骑行中自行打开，虽未摔倒仍为严重风险 | severe/high；共情、停止使用和骑行、不复现、已有安全资料、人工安全核实及退换诉求一起评估 |
| 重复爽约与强烈不满 | 两次取消、请假白等、明确要求人工；新时间未知 | 先承认时间损失；进入本地转人工；只问预约号，不再重复整个经过；不报未经核实的安装日期 |
| 退款或换货申请 | 耳机断音、想退换且关心运费；订单/适用政策未知 | 回应退换偏好和运费；人工核对条件及权限；不让客户反复测试，也不擅自承担运费或许诺退款 |
| 诉求信息不清 | 只有“上次那个问题”，具体商品/事件/历史缺失 | 不猜商品或责任；承认重复沟通负担，以编号或一句话澄清二选一，转人工阅读 |
| 客户要求人工客服 | “人工客服”及不想重复自动说明清楚；业务诉求未知 | 尊重明确请求，保留上下文，服务编号可选；本地演示转交不等于真实坐席接通 |

自定义来信只保存未知占位；可复用既有确定性严重风险锚点作为候选提醒，但不提供通用语义理解、自由问答或质量认证。英文来信得到英文补资料草稿，中文来信得到中文草稿。当前新增中文场景的任意后续邮件仍为 unknown；旧版固定相机第二轮演示保留，不把固定匹配夸大为任意多轮推理。

## 可直接核读的回复片段

普通咨询：

> 您已提供型号，不用再重复填写。仅凭型号还不能确认这项功能，需要对照商家提供的官方连接说明。为免买错，先不用急着购买转接头。

配送受损：

> 很抱歉包裹送到时出现了这样的情况，您担心里面的商品受损是可以理解的。……售后人员需要结合这些资料和订单记录，确认适用的退换或其他处理方式。

安全风险：

> 很抱歉发生了这样的情况，骑行中锁扣打开确实会让人害怕。请先停止使用这辆车，不要骑行，也不要为了拍照或录像试骑、测试锁扣。即使这次没有摔倒，车架连接失效仍需要认真对待。

权限判断：

> 退货、换货和运费承担需要人工结合收货时间、商品情况及适用政策确认。您可以先说明更倾向退货还是换货，这有助于人工评估对应选项。

完整来信、回复、证据和资料清单可在新模块及新工作库中逐条核读。以上是内容设计示例，不给出未经真人评价的“回复准确率”。

## 信息架构

- 智能接待默认：首页三栏，任务/场景、当前邮件与回复、理解与原文依据。空库直接预览咨询及明确预写建议，点击载入后才建立案例；不会静默造业务数据。
- 业务分析：P4独立分母、来源版本隔离、问题和商品/门店分组、成员下钻；旧P3及400模板合成统计保留入口。
- 研究与开发者工具：旧单条、CSV、Evaluation、历史真实重放、完整运行身份与事件、真实LangChain边界说明。组件错误单独呈现。

## 邮件往返纵向切片

不改变 ProductStore SQLite v1、分析 Schema 或旧快照。新建同目录独立 `*-threads.sqlite3`，仅保存不可变父子关联和上下文快照。客户消息来自不可变原始输入；客服消息来自已保存模拟回执，草稿未发送不得成为已发送历史。每条含发送方、时间、case/issue关联、来源与内容hash。子案例仍经 AnalysisService → 原契约/Evidence → ProductStore → 原质量门禁与审核。

上下文组装为显式带角色的文本输入；证据跨度绑定该输入，原消息单独保留。预设相机第二轮严格匹配初始邮件和新增正文；型号由客户提供、未经核实，缺官方规格仍不确认有线能力。任意其他新增正文走显式unknown占位；不宣称动态多轮模型。父案例必须模拟发送；每个父案例只有一个后续节点，重复输入幂等，冲突不覆盖。关联写失败后重试复用已存分析。旧审核阻断不可因新增邮件或润色绕过。

## 验收

测试消息不可变、上下文来源/hash、幂等/冲突、重启恢复、往返草稿变化、不虚构规格、原severe/high不可绕过、回复编辑重新审核。全量离线/portable网络阻断；实际浏览器1366×900、1440×900、窄屏，普通咨询/配送受损/三问题/严重风险/编辑审核模拟/后续邮件/历史重读/看板/CSV与Evaluation。结果按实际证据记录，不以fixture工程通过代替模型质量或真人验收。

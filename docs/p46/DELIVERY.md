# P4.6 中文客户收件箱与 AI 助手

2026-10-28。在 P4.5 `6cdb7ee` 上增量实现，保留 P4 状态机、独立工作库、不可变线程、原分析契约和全部研究资产。新模型调用 **0**，真实 SMTP/CRM 发送 **0**。这是可操作的离线预写演示和历史重放，不宣称实时生成或模型语义认证。

## 直接体验

在项目根目录运行（`--out` 必须是新的目录）：

```powershell
.\.venv\Scripts\python.exe -B scripts/p46_demo.py --out .local/p4/P46_NEW_DEMO --serve --port 8546
```

打开 [本地演示](http://127.0.0.1:8546)。演示脚本复用原 `p45-authored-v1` 的九个明确合成场景，原输入 hash、原场景来源及未审核身份保留。

研究者演示流程：

1. 在「智能客服」收件箱选择「相机是否支持有线连接？」；中间客户原文、右侧诉求及建议同步切换。
2. 点击右侧「插入回复草稿」。建议进入中栏，保存为新版本，来源标为 AI 内部建议。再次插入时必须明确选择追加或替换；可取消保留原稿。
3. 修改回复，点击「保存草稿」；在「版本与处理」查看已保存版本 Diff 与当前未保存差异。
4. 点击「提交审核」，选择演示验收身份，填写说明并逐项核对。未完成核对时不能批准；这不会代签真人质量评价。
5. 批准后仅突出「模拟发送」。点击后消息区出现带身份和时间的客服模拟回复；刷新或重启仍保留回执，终态没有重复发送按钮。
6. 在回执下保存预设客户后续来信。第二轮引用 DemoCam C200，不重复询问型号，仍等待官方规格，不能凭空确认有线能力。
7. 切换到配送受损、三个问题和严重安全风险案例；折叠车错误分析即使插入或编辑回复也不能通过审核。任何新自定义邮件只保存 unknown 占位，不能冒充 AI 理解。

1366/1440 桌面三栏同屏，消息、收件箱和助手局部滚动；1024/768 通过「收件箱 / 对话 / AI助手」切换工作区域，选择或插入后返回对话。未保存编辑按案例和版本缓存在当前浏览器会话；刷新只能恢复已保存版本。

需要恢复同一工作库时，不再次执行种子脚本：设置 `COMPLAINT_PRODUCT_DB` 为该目录的 `product.sqlite3`，`COMPLAINT_DB_PATH` 为该目录的 `legacy.sqlite3`，再启动 `streamlit run app.py`。保留产品、分析、线程三份 SQLite。应用仍强制关闭 paid/live/tracing。

## 真实能力与边界

- 「智能客服」是中文主流程；「业务分析」保留商品、门店、原因、业务来源、情绪、日期并增加风险维度，按原完整来源版本组独立计算，展示 unknown/failed/fallback 与成员原文。模拟发送不等于问题已解决；不同版本组不拼成市场排名。
- 「研究工具」保留旧 Single Analysis、CSV legacy_mock、Dashboard、Evaluation、原始 run 和开发者说明。普通客服界面不展示 Run ID、Hash、Schema 或绝对 SQLite 路径。
- 当前助手读取原始建议；没有新增知识库或虚构品牌规则。追问框明确禁用。四种来源分清：预写 Fixture/unknown、历史真实重放、SDK Mock HTTP、未来实时 DeepSeek（关闭）。
- 新 `insert_suggestion` 使用既有 ProductStore 事务，绑定原建议 run/input/hash；同文插入也保存新版本并回到待审核，已拒绝状态仍要求实际修改内容。原 revision 冲突、审核清单、质量门禁、不可变记录、模拟发送幂等均保留，不迁移数据库。
- 独立 Human Gold、holdout、真实回复语义认证及任意多轮模型推理仍 pending。预写演示通过不代表模型质量。

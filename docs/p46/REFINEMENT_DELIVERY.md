首封邮件紧接下一步与回复编辑器；多轮线程在局部滚动，展示真实保存的来信和模拟回执，不生成填充消息。下一步随草稿、审核、风险状态变化。正文/编辑器16px，建议15px，时间/来源/辅助文字13px，去除辅助文字的0.6透明度。窄屏继续使用工作区域切换。

右侧“证据问答”提供真正可操作的**离线证据问答**：可输入自然语言，也可选择常见问题，再点击“依据本案回答”。支持诉求、保存分类与原文、Issue、待补资料、质量风险、下一步、已提供信息。展开依据可检查逐字客户陈述和质量快照。规则不解释模型内部推理，不认证草稿完整性；对缺少规格或超出范围明确拒答。

例：相机第二轮问“哪些信息已经提供，不能重复询问？”，答案引用线程里的 `DemoCam C200`。问“规格支持有线吗？”明确需要商家官方规格，型号不能证明能力。配送案例问“为什么判为投诉？”返回保存分类及雨淋损坏原文；来源仍标明为演示预测。

问答不修改邮件、历史预测、草稿或审核状态。可用回复仍要在“AI助手”明确点击“插入回复草稿”，保存版本并人工审核。风险阻断不能靠问答、编辑或插入解除。问答不是研究者人工Gold。

## 实时能力边界

独立 CopilotService → CopilotProvider 复用真实 LangChain / ChatOpenAI / DeepSeek 适配。输入包含Case、当前问题、角色明确的保存线程、Issue/Evidence、草稿/质量状态和演示操作资料；固定系统约束将所有邮件及问题视为不可信数据。输出保存回答、引用、不确定性、建议动作、模型、Prompt、Run及用量。SDK Mock HTTP验证输入、持久化、Schema/引用/用量拒绝、超时、服务失败、请求预算及幂等；没有真实Provider自由问答结果。

本轮 live 硬关闭，不能用标签代替MockTransport。未来仍需独立付费/数据范围授权、新的受控实时预算与Provider验证、语义及引用评审，然后才可开放真实模式。现有Mock预算不能消费历史额度；Mock通过不能当作真实模型质量。

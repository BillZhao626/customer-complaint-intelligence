# P5独立质量认证执行准备 v1（待研究者批准）

本文件是可执行提案，不是付费授权或Gold。旧P3.9 71/72与P3.10 180/180不复用。当前用户授权只覆盖工程、离线验证和材料准备。研究者先填写末尾决策清单，再按下列门禁推进。

## 任务、角色与数据隔离

任务固定为“从邮件原文抽取全部当前问题、情绪、投诉状态、原因、归属证据、风险/紧急度/客户重要性；生成无虚构执行能力的可审核回复”。业务归属只作客户描述与建议处理团队，不输出已证实因果/法律责任。七字段投影与多Issue原生任务分开评分。

角色：研究者确认业务政策/范围；数据保管人记录来源与暴露，不参与候选调参；标注者A、B分别在看不到模型输出和对方标签时标注；第三位仲裁者逐条裁决；执行者只能访问冻结输入，不能读取Gold；内容评分者拿匿名A/B回复，不知候选身份。真实姓名/身份由研究者线下核验，脚本只检查声明与hash，不能认证真人。Codex不填写真人签名。

旧400、80、12、24、32、新40、N03自然改写以及其同源改写/翻译/近重复全部列为已暴露开发材料。先建source_id → parent_ids → template_family → semantic_family图，连通分量整族隔离。精确文本hash忽略ID；字符相似度只作筛查，双语语义/翻译/同事件须人工复核。0近重复不等于独立。保管人对新集签署暴露清单；一旦用于调参，该族永久转开发，不能改名holdout。

## LLM新合成数据提案（尚未执行）

独立新目录 `llm_synthetic_v1`，旧400不动。建议先12封开发冒烟：商品/服务/物流各至少2，余量覆盖表扬、咨询、多Issue、未知归属、严重风险、中英混合；生成与分析用不同任务/账本。每封一条请求，最多12生成请求、不隐式重试；人工拒绝样本也留存，替补需要另留版本和授权计数。生成不要求模型输出“Gold”。

生成指令模板：给定场景族、语言、单/多问题、事实完整度和目标长度，写一封虚构自然邮件；不含真实个人联系方式、真实订单或现实企业投诉；避免直接暴露分类标签；允许不确定信息且不可凭空补全原因。保存原Prompt、参数、provider/alias、响应ID、raw、时间、tokens、input/output hash、生成模型与分析模型关系、人工接受/拒绝原因。不是调用分析模型给自己出题并自判。

两位审核者检查自然度、矛盾、缺必要信息、标签泄漏、模板相似性、风险合理性。12封只作流程可行性，不作认证。建议正式120封，分为六个互斥主采样层各20：产品投诉、门店/售后、物流/账单、表扬/非投诉咨询、混合/多问题、严重安全或责任不清；额外多标签覆盖语言/风险/重要性。分层数量与真实人群无关，不加权称市场表现。数据量和层额是待批准提案；若严重Gold阳性不足，补充独立层或承认统计功效不足。

生成预算分开登记：12请求×每次输入上界I/输出上界O，费用上界 `12×(I×p_in+O×p_out)/10^6`；例如I=4000/O=2000仅为计算参数提案，不是现行价格/额度。研究者须在执行当日核对官方价格、模型、数据范围、有效期和最大人民币额度，达到请求数或金额任一上限停止。当前无真实生成记录。

## 空白工作表与准备命令

可复用 `src/evaluation/gold.py` 的独立声明、双人分歧、仲裁与追加冻结逻辑，但其原生范围为v2七字段；`e2e_v3.py` 当前候选协议限定已暴露开发，不能用它伪装P5独立集。本轮不迁移旧评价契约；新准备材料以明确P5 sidecar形式保存，正式v3.1 Gold计分器适配须在Gold冻结前另作版本验收。

`scripts/p5_preflight.py` 只准备空白材料，无provider、无自动标注、无Gold冻结。输入JSON数组每行：email_id、subject、body、source_kind、source_ref、template_family、semantic_family、parent_ids。来源按事实填 `llm_generated`、`human_authored` 或 `explicit_test_fixture`，不得回填旧来源。

```powershell
.\.venv\Scripts\python.exe -B scripts/p5_preflight.py prepare --inputs PRIVATE_NEW_INPUTS.json --exposed PRIVATE_EXPOSED_INDEX.json --out .local/p5/NEW_BLIND_PACKET
.\.venv\Scripts\python.exe -B scripts/p5_preflight.py check --manifest .local/p5/NEW_BLIND_PACKET/manifest.json --packet .local/p5/NEW_BLIND_PACKET/reviewer-A.json
```

输出manifest、A/B独立空白工作表、仲裁表和回复评分表。全部签名null、标签null、holdout=false；check只给绑定/基本完整性结果，不认证语义或独立性。准备目录必须新建，不能覆盖已有文件。实际离线演示包在 `.local/p4/final-20261026/p5-blank-demo/`，仅显式fixture，不能进入P5测试集。

每个Issue工作表填写：人工issue_id、对象/类别、问题类型、原因、情绪、解决状态、业务来源/路由/确定性、风险、紧急度及依据、客户主次、处理顺序、诉求和缺证信息。每项结论附subject/body、0基Python Unicode code-point起止、逐字quote、理由、certainty；明确unknown或not_applicable与未标注null不同。跨问题equal/primary关系单独记录，不把处理顺序当客户偏好。

先冻结原文/Gold再生成模型输出。保存A/B原件、分歧、原始一致率与Cohen κ（同一类别导致分母0时null）、仲裁者理由、最终Gold和全部hash。修订追加版本，不覆盖旧标签；不得看到分数后修Gold提高成绩。对合法歧义可提前登记等价答案集合，不能事后按模型答案扩集合。

## 评价公式及Rubric

所有指标输出定义、分子/分母、来源版本、适用集、缺失数。预注册N；failed/unknown dispatch/missing/fallback不从端到端分母删除。unknown是真实类别，失败哨兵不是unknown，不可因两者相等得分。conditional-on-accepted可另报但不可替代全量主结果。

|项目|固定公式与操作规则|
|---|---|
|字段|正确字段/(N×字段数)；单字段correct/N；macro-F1与每类支持数；邮件全对=全部必评字段正确的邮件/N|
|结构|JSON合法/N、wire Schema合法/N、完整契约接受/N；失败原因与是否收到响应分开|
|Issue|由盲态人工先匹配“同对象+同事件”一一对应，不依据模型reason/情绪来决定匹配；重复预测多余项计FP，漏项计FN；P=TP/(TP+FP)、R=TP/(TP+FN)、F1=2PR/(P+R)。分母0时null并列n；失败邮件所有Gold Issue为FN。现有贪心跨度算法仅作辅助/敏感性分析|
|Issue字段|匹配后正确值/Gold issue数；漏识别计错，误增Issue单列FP；邮件Issue集合全对/N；重要性与业务顺序独立|
|Evidence|逐字合法跨度/所有预测跨度；语义支持跨度/已人工判断预测跨度；Gold要求已被支持的判断/全部Gold要求判断。分别披露预测跨度数、人工评分覆盖，不能用逐字正确代语义支持|
|风险|Gold severe且未预测severe/high的数/Gold severe数；误报severe数/Gold非severe数。failed/missing算漏判；停止使用建议缺失另记；未知不能隐藏漏判|
|归属/投诉状态|无支持的确定归因数/有归因预测数；未解决投诉被弱化为咨询/非投诉数/Gold未解决投诉数；unknown准确率与unknown占比独立|
|摘要/回复|每维0/1/2；0=事实错/遗漏关键诉求/危险或虚构能力，1=部分正确但需实质修改，2=可由原文支持且满足约束。维度：事实、覆盖、证据支持、安全、执行权限、语气清晰语言、可编辑就绪。严重错误单独boolean，不被平均分抵消|
|人类内容通过|所有必要维度=2且无critical的输出数/被独立评分输出数；另报同一通过数/N的端到端可用率、评分覆盖/N、修改字符比例及实质修改率|
|成本/延迟|所有请求tokens和费用/N；首轮与纠错分别累计；p50/p95写n与计时边界；缺usage=null且停止派发；缓存实际账单未知时仅保守估算|

盲评顺序随机且记录seed；候选名称隐去，A/B顺序交换。两名真人独立评分，仲裁保留双方分数。若以后加LLM Judge，只能作次级辅助：冻结judge/model/prompt、与待测模型分离、顺序互换、控制冗长偏差、对人工Gold分层校准、报告不一致；不拿待测模型自评证明自身准确率。此项本轮未实现。

配对比较固定同一输入、同一Gold、同一契约和同等预算，交错调用。两臂均最多1次显式纠错，仅原严格拒绝触发；同样4000输出上限等参数需在profile中冻结并与provider约束一致。首轮、纠错条件集和最终工作流分别比较；原P3.10只给Challenger纠错的结果不能充当公平P5比较。配对差分以邮件/语义族为重采样单位，预注册seed、10000次cluster bootstrap 95%区间，接受二分类另给McNemar；不能按字段当独立样本缩小区间。

## 预算、停止与晋升门禁（提案，未批准）

正式120封×2臂×最多2次=480次请求上限，生成请求另账；预算不足不启动正式比较或预先减小N，不能中途只给某一臂纠错。费用采用执行日前核验价格与输入token上界，人民币硬限额由研究者填写，空缺即禁止执行。请求白名单、精确config/prompt/schema/policy/source/dependency hash、期限、价格来源、用途与账本路径共同绑定；不得复制或复活旧账本。未知发送、模型身份/usage漂移、未持久化、超预算/到期立即停止所有新请求并保留lease。质量拒绝记录后继续预定计划；发现新严重风险暂停该候选产品启用，不回写分数。

建议认证门禁：零经仲裁确认的严重风险漏判、零虚构退款/联系/已执行操作等critical；完整契约接受率≥90%、回复端到端人类通过率≥80%，且候选在配对比较中不降低风险召回/状态保护。阈值是待研究者批准建议，不是已达标事实；小样本零漏判不等于零风险（零事件粗略95%上界约3/n，需报告）。未批准不得据此晋升。P3.10 Challenger当前维持禁晋升。
